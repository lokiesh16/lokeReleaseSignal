Set PYTEST_PROJECT_ROOT (cwd, for imports) and PYTEST_TESTS_DIR (where to scan for test_*.py) in .env — defaults to a pytest_tests/ folder next to the bridge server. Set PYTEST_TESTS_PYTHON too if that suite needs a different venv. To turn on Slack posting for these runs, add {"slack_webhook_url": "${SLACK_WEBHOOK_URL}"} to a _defaults.meta.json file at the root of that tests folder — one file covers every file/folder run here, or drop a meta.json inside one folder (or a <file>.meta.json next to one file) to override it for just that target. To also publish each run's Allure report to GitHub Pages (so the link in Slack works anywhere, not just on this Mac), add "publish_allure": true to that same meta file and set ALLURE_REPORTS_TOKEN in .env.
Capture API calls while you test by hand

No AI, no automation — you use the app yourself on your phone, just like a real user would. This does not record your taps or what's on screen — it only captures the API calls your phone makes in the background while you use the app. Before you try each thing, type a quick note about what you're about to do — at the end, you'll get a report listing exactly which API calls happened during each thing you tried.

One-time setup, or this will capture nothing: your phone's traffic has to actually pass through this computer first. On this machine, install mitmproxy (pip install mitmproxy). On your phone, point its Wi-Fi proxy settings at this computer's IP address and the port below, then install and fully trust mitmproxy's security certificate (Settings → General → VPN & Device Management, then Settings → About → Certificate Trust Settings on iOS) — without that last step, your phone's traffic is encrypted and none of it can be read.
